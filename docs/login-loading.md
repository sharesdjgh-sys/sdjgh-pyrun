# 로그인 및 학습 화면 로딩

- 직접 접속: 학교명 + 학번 + 비밀번호로 인증. 스마트캠퍼스 호출 없이 세션을 발급한다.
- 플랫폼 iframe: 부모 출처와 메시지 발신자를 확인한 뒤 서버에서 SSO 토큰을 검증한다. 기존 플랫폼 학교 ID 1 매핑을 유지한다.
- 인증 후 /learn은 세션만 확인하고 편집기와 캐릭터를 표시한다. bootstrap, access API와 Python 준비는 병렬로 시작한다.
- 두 API는 요청 파라미터 대신 세션의 학교와 사용자로 범위를 결정하며 private, no-store로 응답한다.
- 단원 접근 상태가 도착하기 전에는 학생의 단원 선택을 잠근다. 조회 실패 시 해당 영역만 재시도한다.
- 기존 전체 진도 API는 성장 기록 화면에 유지한다. 학습 진입용 access API는 완료·해제 ID만 조회한다.
- 학습 자료 로딩 중 입력한 코드는 도착한 기본 예제로 덮어쓰지 않는다.

## 배포

서버 시작 시 DDL을 실행하지 않는다. 이 버전 배포 전 배포 환경의 DB를 대상으로 `npm run db:migrate`를 한 번 실행한다. 로컬 실행은 `.env.local`을 사용한다. CI에서는 환경 변수를 주입하고 `npx tsx scripts/migrate-startup.ts`로 실행한다.

이 명령은 기존 시작 시 수행하던 호환 스키마 변경과 기존 커리큘럼의 누락된 메크독 기본 데이터를 준비한다. 데이터가 없는 기존 커리큘럼을 위해 배포 전에 실행해야 한다. 신규 학교 및 커리큘럼은 생성 시 기본 데이터를 준비한다.

## 운영 검증

1. 두 학교에서 동일 학번 계정으로 직접 로그인하여 학교별 단원과 진도가 분리되는지 확인.
2. 스마트캠퍼스 iframe에서 정상·만료 토큰, 재접속, 로그아웃 후 접속 확인.
3. 네트워크 지연 시 학습 화면 선표시, 단원 잠금, 자료·진도 재시도, 입력 코드 보존 확인.
4. 리뷰 링크와 레벨 전환, Python 실행, 기존 메크독 예제 확인.
5. 로그인 클릭부터 인증 완료, 화면 표시, 자료 준비, Python 준비 시간을 각각 측정. 첫 접속과 재접속을 나누어 비교.

공용 데이터 캐시와 단원별 상세 API는 이 변경에 포함하지 않았다. 우선 기존 콘텐츠와 접근 제어를 유지하면서 로그인 대기에서 데이터 준비를 분리한다.
